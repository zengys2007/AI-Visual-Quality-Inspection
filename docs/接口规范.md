# 电池包视觉质检接口规范

| 项目 | 说明 |
| --- | --- |
| 文档版本 | v1.1 |
| 适用赛题 | 赛题二：电池包瑕疵检测 |
| 基准依据 | 赛题说明书；《附件1：检测结果输出表格规范及字段说明》 |

本文约定可视化应用程序与检测算法之间的**输入、检测结果、批量导出**格式。导出 CSV 必须与附件 1 完全一致，供评分工具读取。

应用程序须支持：图像导入、检测运行、结果可视化（类别、位置、置信度）、检测结果保存与批量导出。未提供可运行的可视化应用视为未完成本任务。

---

## 1. 输入接口

### 1.1 图像

| 项 | 要求 |
| --- | --- |
| 来源 | 主办方统一提供的电池包数据集（训练/验证/测试） |
| 格式 | JPEG、PNG、BMP 等常见工业/通用图像格式 |
| 内容 | 电池包整体区域、表面涂覆区域及相关结构件 |
| 样本 | 正常样本、表面裂纹样本；可含不同外观、角度、光照、裂纹形态与程度 |
| 标识 | 每张图有唯一文件名，检测结果中的 `image_id` 必须与该文件名（含扩展名）完全一致 |

可视化应用应支持选择单张图像或选择文件夹批量导入。

### 1.2 检测触发

| 项 | 要求 |
| --- | --- |
| 单张检测 | 对当前导入图像执行推理，界面立即展示框、类别、置信度与耗时 |
| 批量检测 | 对导入目录中全部图像逐张推理，不得漏图 |
| 纳入范围 | 目录内上述格式的图像文件 |

测试集标签不公开。不得获取或反推测试集标签，不得人工改写测试结果规避统一评价。

---

## 2. 检测结果接口

算法内部可采用目标检测框或实例分割 Mask。对外结果（界面展示框与 CSV）统一为**轴对齐矩形框**。

若为分割 Mask 或轮廓：对每个独立裂纹实例计算外接矩形。

- `x_min` = 该实例全部有效像素（或轮廓点）的最小 X
- `y_min` = 最小 Y
- `x_max` = 最大 X
- `y_max` = 最大 Y

Mask、Polygon 仅作算法内部及界面叠加，**不得替代** CSV 中的四项框坐标。坐标必须是原始图像像素绝对值，禁止归一化。

### 2.1 坐标系与数值

- 原点在图像左上角，X 向右，Y 向下。
- `x_min, y_min` 为框左上角；`x_max, y_max` 为右下角**坐标值**，不是宽高。
- 有缺陷时须满足 `x_max > x_min` 且 `y_max > y_min`。
- `confidence` 取值 `[0, 1]`，保留 2 位小数；无缺陷占位时填 `-1`。
- `inference_time_ms` 为该图**整张**检测总耗时（毫秒）。同一张图多行必须填相同值。

### 2.2 类别名称

| 中文 | `class_name`（大小写必须一致） | 说明 |
| --- | --- | --- |
| 表面裂纹 | `Surface_Crack` | 检出的裂纹实例 |
| 无缺陷（占位） | `Ok` | 该图未检出任何缺陷时必须输出一行 |

本赛题不使用窗帘布类别（`Hole`、`Ink`、`Broken_Filament`）。禁止使用 `crack`、`表面裂纹` 等非规定值。

### 2.3 结果记录（一行一目标）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `image_id` | 字符串 | 是 | 图像文件名，含扩展名，如 `test_001.jpg` |
| `class_name` | 字符串 | 是 | `Surface_Crack` 或 `Ok` |
| `confidence` | 浮点数 | 是 | `[0, 1]`，保留 2 位小数；`Ok` 时为 `-1` |
| `x_min` | 整数或浮点数 | 是 | 左上角 X；`Ok` 时为 `-1` |
| `y_min` | 整数或浮点数 | 是 | 左上角 Y；`Ok` 时为 `-1` |
| `x_max` | 整数或浮点数 | 是 | 右下角 X；`Ok` 时为 `-1` |
| `y_max` | 整数或浮点数 | 是 | 右下角 Y；`Ok` 时为 `-1` |
| `inference_time_ms` | 浮点数 | 是 | 该图检测总耗时（ms） |

填写规则：

1. 每个裂纹实例对应一条记录。
2. 一图多裂纹时，同一 `image_id` 出现多行，每行一个框。
3. 未检出任何缺陷时，必须恰好一行 `Ok`：`confidence` 与四个坐标均为 `-1`，耗时填实际值。严禁某张图完全不出现，否则评分无法统计测试图片总数。
4. 已检出裂纹时，该图不得再写 `Ok` 行。
5. 界面可额外显示 OK/NG、Mask、颜色叠加等；提交评分只认下节 CSV 八列。

界面展示的类别、位置、置信度须与导出记录一致。

## 3. 批量导出接口（评分提交）

可视化应用必须提供检测结果批量导出。

| 项 | 要求 |
| --- | --- |
| 格式 | CSV，逗号分隔，UTF-8 |
| 文件名 | `团队名称_检测结果.csv`（例：`视觉检测团队_检测结果.csv`） |
| 表头 | 必须包含下表全部 8 列，列名严格一致（区分大小写），禁止改名、增减、调序 |

表头：

```text
image_id,class_name,confidence,x_min,y_min,x_max,y_max,inference_time_ms
```

电池包示例：

```csv
image_id,class_name,confidence,x_min,y_min,x_max,y_max,inference_time_ms
pack_001.jpg,Surface_Crack,0.88,50,60,180,140,33.1
pack_001.jpg,Surface_Crack,0.76,400,220,470,300,33.1
pack_002.jpg,Ok,-1,-1,-1,-1,-1,29.4
```

目录中每一张被检测的图像都必须出现在 CSV 中（有裂纹则多行，无裂纹则一行 `Ok`）。

## 4. 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 坐标用归一化值（如 0.5） | IoU 错误，mAP 失真 | 使用像素绝对值（如 250） |
| `x_max` / `y_max` 填成框宽/框高 | 坐标解析失败 | 填右下角坐标（左上角 + 宽/高） |
| 同一张图多行总耗时不一致 | 平均推理时间算错 | 同一 `image_id` 各行填相同总耗时 |
| 无缺陷图不写任何行 | 测试图片总数遗漏 | 必须写一行 `Ok` 占位 |
| 类别名未用规定值 | 该预测被忽略 | 只用 `Surface_Crack` 或 `Ok` |

## 5. 提交前核对

- [ ] 表头 8 列名称、顺序、大小写与附件 1 一致
- [ ] `image_id` 含扩展名，与测试集文件名逐字相同
- [ ] `class_name` 仅为 `Surface_Crack` 或 `Ok`
- [ ] 有框时 `confidence ∈ [0, 1]` 且保留 2 位小数
- [ ] `Ok` 行：`confidence` 与四坐标均为 `-1`，耗时为真实值
- [ ] 非 `Ok` 时 `x_max > x_min`、`y_max > y_min`
- [ ] 坐标为像素绝对值，非归一化、非宽高
- [ ] 分割结果已转为外接矩形
- [ ] 每张检测图至少一行，无漏图
- [ ] 同图多行耗时一致
- [ ] 文件名为 `团队名称_检测结果.csv`，UTF-8
- [ ] 应用可完成导入、检测、可视化、导出
