# 电池包视觉质检接口规范

| 项目 | 说明 |
| --- | --- |
| 文档版本 | v1.0 |
| 适用赛题 | 任务二：电池包瑕疵检测 |
| 服务名称 | AI Visual Quality Inspection（电池包） |
| 基准依据 | 《附件1：检测结果输出表格规范及字段说明》 |
| 传输编码 | UTF-8 |
| 协议 | HTTP/1.1，REST + JSON |

本文约定可视化应用程序对外提供的检测、查询与结果导出接口。导出 CSV 必须与附件 1 字段完全一致，供评分工具读取。

---

## 1. 约定

### 1.1 服务地址

| 环境 | Base URL |
| --- | --- |
| 本地开发 | `http://127.0.0.1:8000` |
| 赛场部署 | 由现场配置，下文以 `{BASE}` 表示 |

所有接口路径均相对于 `{BASE}`。

### 1.2 通用请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Content-Type` | 是 | JSON 请求为 `application/json`；上传图片为 `multipart/form-data` |
| `Accept` | 否 | 默认 `application/json` |
| `X-Request-Id` | 否 | 调用方追踪 ID；未传时服务端生成 UUID |

### 1.3 统一响应信封

成功与业务失败均返回 JSON，HTTP 状态码见第 6 节。

```json
{
  "code": 0,
  "message": "ok",
  "request_id": "c8a1e2d0-3f11-4b2a-9c0a-1a2b3c4d5e6f",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | `0` 成功；非 0 为错误码 |
| `message` | string | 人类可读说明 |
| `request_id` | string | 本次请求 ID |
| `data` | object / array / null | 业务数据；失败时可为 `null` |

### 1.4 坐标系与数值

- 图像坐标系原点在左上角，X 向右，Y 向下。
- 框坐标为**原始图像像素绝对值**，禁止归一化（如 `0.5`）。
- `x_min, y_min` 为轴对齐外接矩形左上角；`x_max, y_max` 为右下角坐标值，**不是宽高**。
- 须满足 `x_max > x_min` 且 `y_max > y_min`（`Ok` 占位行除外）。
- `confidence` 取值 `[0, 1]`，保留 2 位小数；`Ok` 时填 `-1`。
- `inference_time_ms` 为**该图整张推理总耗时**（毫秒，浮点）。同一 `image_id` 多行必须填相同值。

### 1.5 缺陷类别（电池包）

| 中文 | `class_name`（须严格一致） | 说明 |
| --- | --- | --- |
| 表面裂纹 | `Surface_Crack` | 检出的裂纹实例 |
| 无缺陷（占位） | `Ok` | 该图未检出任何缺陷时必须输出一行 |

本任务不使用窗帘布类别（`Hole` / `Ink` / `Broken_Filament`）。类别名大小写敏感，禁止使用 `crack`、`表面裂纹` 等非规定值。

实例分割或轮廓结果须先转为轴对齐外接矩形再对外输出：

- `x_min` = 该实例全部有效像素（或轮廓点）的最小 X
- `y_min` = 最小 Y
- `x_max` = 最大 X
- `y_max` = 最大 Y

Mask、Polygon 仅作算法内部结果，**不得替代**上述四项框坐标。

## 2. 检测结果对象

接口 JSON 与导出 CSV 共用同一套字段语义。

### 2.1 `DetectionItem`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `image_id` | string | 是 | 图像文件名（含扩展名），须与测试集文件名完全一致，如 `test_001.jpg` |
| `class_name` | string | 是 | `Surface_Crack` 或 `Ok` |
| `confidence` | number | 是 | `[0, 1]` 保留 2 位小数；`Ok` 时为 `-1` |
| `x_min` | number | 是 | 左上角 X；`Ok` 时为 `-1` |
| `y_min` | number | 是 | 左上角 Y；`Ok` 时为 `-1` |
| `x_max` | number | 是 | 右下角 X；`Ok` 时为 `-1` |
| `y_max` | number | 是 | 右下角 Y；`Ok` 时为 `-1` |
| `inference_time_ms` | number | 是 | 该图检测总耗时（ms） |

填写规则：

1. **一行一目标**：每个裂纹实例对应一条 `DetectionItem`。
2. **一图多缺陷**：同一 `image_id` 可出现多条，每条一个框。
3. **无缺陷图**：必须恰好一条 `Ok` 占位（`confidence` 与四个坐标均为 `-1`，耗时填实际值）。禁止该图在结果集中完全缺失。
4. 有缺陷时**不得**再附带该图的 `Ok` 行。

## 3. 接口列表

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| POST | `/api/v1/inspect` | 单张检测（上传文件） |
| POST | `/api/v1/inspect/path` | 单张检测（服务端本地路径） |
| POST | `/api/v1/inspect/batch` | 批量检测测试集目录 |
| GET | `/api/v1/results` | 查询当前会话/任务检测结果 |
| GET | `/api/v1/results/{image_id}` | 按图查询 |
| GET | `/api/v1/export/csv` | 导出评分用 CSV |
| DELETE | `/api/v1/results` | 清空当前结果缓存 |

## 4. 接口详细说明

### 4.1 健康检查

**GET** `/health`

**响应 `data` 示例**

```json
{
  "status": "up",
  "model_loaded": true,
  "task": "battery_pack",
  "version": "1.0.0"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | string | `up` / `degraded` / `down` |
| `model_loaded` | boolean | 裂纹检测模型是否已加载 |
| `task` | string | 固定 `battery_pack` |
| `version` | string | 应用版本 |

---

### 4.2 单张检测（上传）

**POST** `/api/v1/inspect`

`Content-Type: multipart/form-data`

| 表单字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | 待检图像（jpg / jpeg / png / bmp） |
| `image_id` | string | 否 | 覆盖文件名作为 `image_id`；默认使用上传文件名（含扩展名） |

**成功 `data`**

```json
{
  "image_id": "test_001.jpg",
  "width": 1920,
  "height": 1080,
  "inference_time_ms": 41.6,
  "defect_count": 2,
  "items": [
    {
      "image_id": "test_001.jpg",
      "class_name": "Surface_Crack",
      "confidence": 0.93,
      "x_min": 120,
      "y_min": 80,
      "x_max": 340,
      "y_max": 210,
      "inference_time_ms": 41.6
    },
    {
      "image_id": "test_001.jpg",
      "class_name": "Surface_Crack",
      "confidence": 0.81,
      "x_min": 800,
      "y_min": 400,
      "x_max": 960,
      "y_max": 520,
      "inference_time_ms": 41.6
    }
  ]
}
```

无缺陷时 `defect_count` 为 `0`，`items` 仅含一条 `Ok` 记录。

可视化界面可在 `items` 基础上绘制矩形框；分割 Mask 如需展示，由实现方通过独立内部接口提供，**不进入评分 CSV**。

---

### 4.3 单张检测（本地路径）

**POST** `/api/v1/inspect/path`

`Content-Type: application/json`

```json
{
  "image_path": "D:/dataset/test/test_010.jpg"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `image_path` | string | 是 | 服务端可访问的绝对或相对路径 |

`image_id` 取路径的文件名字段（含扩展名）。响应结构同 4.2。

---

### 4.4 批量检测

**POST** `/api/v1/inspect/batch`

用于对主办方测试集目录整目录推理，并写入结果缓存供导出。

```json
{
  "input_dir": "D:/dataset/test",
  "recursive": false,
  "clear_previous": true
}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `input_dir` | string | 是 | — | 测试集目录 |
| `recursive` | boolean | 否 | `false` | 是否递归子目录 |
| `clear_previous` | boolean | 否 | `true` | 是否清空已有结果后再写入 |
| `extensions` | string[] | 否 | `[".jpg", ".jpeg", ".png", ".bmp"]` | 纳入检测的后缀（大小写不敏感） |

**成功 `data`**

```json
{
  "job_id": "job_20261005_150000",
  "image_total": 100,
  "image_ok": 72,
  "image_ng": 28,
  "instance_total": 41,
  "avg_inference_time_ms": 36.4,
  "elapsed_ms": 3720.0
}
```

| 字段 | 说明 |
| --- | --- |
| `job_id` | 本次批量任务 ID |
| `image_total` | 处理图片数（每张图至少 1 条结果） |
| `image_ok` | 无缺陷图数量（仅 `Ok` 行） |
| `image_ng` | 至少 1 个 `Surface_Crack` 的图数量 |
| `instance_total` | `Surface_Crack` 实例总数（不含 `Ok`） |
| `avg_inference_time_ms` | 按**图**去重后的平均单张耗时 |
| `elapsed_ms` | 批量任务墙钟耗时 |

目录中每一张符合后缀的图片都必须进入结果集；漏图会导致评分分母错误。

---

### 4.5 查询全部结果

**GET** `/api/v1/results`

| Query | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `job_id` | string | 否 | 指定批量任务；默认当前缓存 |
| `class_name` | string | 否 | `Surface_Crack` 或 `Ok` |
| `image_id` | string | 否 | 精确匹配文件名 |

**成功 `data`**

```json
{
  "total": 3,
  "items": [
    {
      "image_id": "pack_001.jpg",
      "class_name": "Surface_Crack",
      "confidence": 0.88,
      "x_min": 50,
      "y_min": 60,
      "x_max": 180,
      "y_max": 140,
      "inference_time_ms": 33.1
    },
    {
      "image_id": "pack_001.jpg",
      "class_name": "Surface_Crack",
      "confidence": 0.76,
      "x_min": 400,
      "y_min": 220,
      "x_max": 470,
      "y_max": 300,
      "inference_time_ms": 33.1
    },
    {
      "image_id": "pack_002.jpg",
      "class_name": "Ok",
      "confidence": -1,
      "x_min": -1,
      "y_min": -1,
      "x_max": -1,
      "y_max": -1,
      "inference_time_ms": 29.4
    }
  ]
}
```

`items` 顺序建议：先按 `image_id` 字典序，同图按 `y_min, x_min` 升序。

---

### 4.6 按图查询

**GET** `/api/v1/results/{image_id}`

`image_id` 需 URL 编码，例如 `pack_001.jpg`。

响应 `data` 与 4.2 的单张结构相同。若该图尚未检测，返回错误码 `40401`。

---

### 4.7 导出 CSV（评分提交文件）

**GET** `/api/v1/export/csv`

| Query | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `team_name` | string | 是 | 团队名称，用于文件名 |
| `job_id` | string | 否 | 指定任务；默认当前全部结果 |

**响应**

- HTTP `200`
- `Content-Type: text/csv; charset=utf-8`
- `Content-Disposition: attachment; filename="{团队名称}_检测结果.csv"`

文件要求（与附件 1 一致）：

| 项目 | 要求 |
| --- | --- |
| 格式 | CSV，逗号分隔，UTF-8（建议带 BOM 以便 Excel 打开，评分工具按 UTF-8 解析即可） |
| 文件名 | `{团队名称}_检测结果.csv`，例：`视觉检测团队_检测结果.csv` |
| 表头 | 必须且仅须以下 8 列，列名大小写与顺序必须一致 |

表头（第一行，禁止改名、禁止增减列）：

```text
image_id,class_name,confidence,x_min,y_min,x_max,y_max,inference_time_ms
```

**电池包合法示例**

```csv
image_id,class_name,confidence,x_min,y_min,x_max,y_max,inference_time_ms
pack_001.jpg,Surface_Crack,0.88,50,60,180,140,33.1
pack_001.jpg,Surface_Crack,0.76,400,220,470,300,33.1
pack_002.jpg,Ok,-1,-1,-1,-1,-1,29.4
```

实现约束：

- 检测出裂纹：每实例一行，`class_name=Surface_Crack`。
- 未检出：一行 `Ok,-1,-1,-1,-1,-1,{实际耗时}`。
- 同一 `image_id` 各行 `inference_time_ms` 必须相同。
- 不得输出归一化坐标；不得把宽高写入 `x_max` / `y_max`。

---

### 4.8 清空结果

**DELETE** `/api/v1/results`

可选 Query：`job_id`。成功时 `data`：

```json
{
  "cleared": true
}
```

## 5. 可视化程序与接口的关系

```text
[测试集图像] --> POST /inspect 或 /inspect/batch
                      |
                      v
              [推理引擎：分割/检测]
                      |
          实例 -> 轴对齐外接矩形 + 置信度
                      |
        +-------------+-------------+
        |                           |
   界面叠加显示框              结果缓存
        |                           |
        v                           v
  操作员查看裂纹             GET /export/csv
                                   |
                                   v
                    {团队}_检测结果.csv  --> 评分工具
```

界面可额外展示裂纹 Mask、置信度颜色、耗时等，但提交评分**只认 CSV 八列**。

## 6. 错误码

| HTTP | `code` | 含义 |
| --- | --- | --- |
| 200 | 0 | 成功 |
| 400 | 40000 | 请求体/表单不合法 |
| 400 | 40001 | 缺少文件或路径 |
| 400 | 40002 | 图像无法解码 |
| 400 | 40003 | `team_name` 非法（空、含路径分隔符等） |
| 404 | 40400 | 接口不存在 |
| 404 | 40401 | 指定 `image_id` 无结果 |
| 404 | 40402 | `input_dir` 不存在 |
| 409 | 40900 | 结果为空，无法导出 |
| 500 | 50000 | 服务内部错误 |
| 503 | 50300 | 模型未加载 |

错误响应示例：

```json
{
  "code": 40002,
  "message": "无法解码图像文件",
  "request_id": "c8a1e2d0-3f11-4b2a-9c0a-1a2b3c4d5e6f",
  "data": null
}
```

## 7. 校验清单（实现与提交前）

- [ ] 表头 8 列名称、顺序、大小写与附件 1 完全一致
- [ ] `image_id` 含扩展名，与测试集文件名逐字相同
- [ ] `class_name` 仅为 `Surface_Crack` 或 `Ok`
- [ ] 有框时 `confidence ∈ [0,1]` 且保留 2 位小数
- [ ] `Ok` 行：`confidence` 与四坐标均为 `-1`，耗时为真实值
- [ ] `x_max > x_min`，`y_max > y_min`（非 `Ok`）
- [ ] 坐标为像素绝对值，非归一化，非宽高
- [ ] 分割结果已转为外接矩形
- [ ] 每张测试图至少一行；无漏图
- [ ] 同图多行耗时一致
- [ ] 文件名为 `团队名称_检测结果.csv`，UTF-8

常见错误与后果见附件 1 第 5 节：归一化坐标会导致 IoU/mAP 失真；宽高误当右下角会导致评分解析失败；漏写 `Ok` 行会导致图片总数统计错误。
